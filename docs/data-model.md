# 数据模型与计算规则

当前数据库以 `src/backend/database/schema.sql` 为准（schema v6）。只初始化空库或重开 v6；用户明确不需要 migration，旧迁移文件已移除。以下对应当前表与领域规则；所有用户数据表和关联都有用户归属。

## 实体

| 实体 | 内容与约束 |
| --- | --- |
| users / sessions | 用户、凭据哈希、会话撤销；会话令牌只保存安全摘要 |
| health_connections / sync_coverage | user_id、平台、客户端安装身份、按类型同步覆盖状态 |
| raw_files | user_id、文件 ID、relative_path、摘要、MIME、大小、页数；可选 processing_path/processing_sha256 必须同时出现 |
| reports / report_relations | 当前一个文件对应一份报告；版本、背景、重复或替代关系 |
| extraction_pages / extraction_outputs | 页面状态与候选；按 run/page/stage 保存完整回复、HTTP 状态、可解析正文、model/adapter |
| observations / observation_revisions | 稳定观测 ID、不可变修订、审核状态、出处、原值与标准化候选 |
| 指标注册表（Rust） | 指标身份、允许单位和转换规则；当前不是数据库表 |
| health_records / health_revisions | 来源原始 ID、平台类型、起止时间、完整 envelope、删除标记、版本；每个有效修订关联 raw_path |
| sync_batches | 连接、批次 ID、载荷摘要、接收回执；重复请求返回相同结果 |
| jobs | 归属、状态、租约、重试次数与安全错误码 |
| analysis_runs / analysis_feedback | 阶段 B 的输入快照、依据、结果历史、人工反馈 |
| cleanup_files / deleted_uploads | 持久文件清理队列和最小上传抑制标记 |
| exports | 数据水位、归档状态、版本化 ZIP；来源变化使旧快照失效 |

复合唯一键至少涵盖用户与来源：健康记录不能只按时间和值判唯一；文件摘要只在同一用户范围提示重复。对外 ID 使用不透明标识，但不能用其不可猜测性替代鉴权。

## 血检结果结构

每项记录保留原始名称、原始结果文本、原单位、参考区间文本、报告异常标记、采样日期、报告日期、页码、坐标或原文片段。明确区分报告中的异常标记与 helpyourself 的计算结果。

结果类型区分精确数值、带比较符的数值、区间、分类、文本、未解析。`<5` 不存成精确的 5，未提供参考区间不补造。手工录入可创建原识别未发现的项目，但必须标记录入来源。

标准化字段包含 metric_id、映射版本、标准单位及转换规则版本。字符串相似不足以合并：需核对样本类型、检测含义和必要的方法差异。不能确定时保持未映射，并允许已确认原文归档而不进入数值比较。

修正产生新修订，保留操作者和原因；转换值从已确认原值计算。乐观版本控制拒绝覆盖他人或另一设备的新修订。审核状态与能否计算分开：已确认的文本结果可以归档但不画连续数值曲线。

## 时间语义

- 血检优先按采样时间展示；仅有日期时保留日期精度，不伪造午夜采血。缺采样日期时标明采用报告日期或未知。
- 平台明细保存原始开始、结束、时区/偏移信息（若来源提供），另存 UTC 查询时间；缺时区标为未知。
- 日聚合请求显式带 IANA 时区；边界按该时区自然日计算，覆盖夏令时与跨日事件。
- 旅行及不同设备时区不能通过永久修改原始时间解决；展示带查询时区。

## 平台明细与覆盖

可索引核心字段加类型化载荷。Apple HKSample 保留 `raw_archive`（NSKeyedArchiver secure archive 的 base64）、精确时间、元数据和关联 ID；FHIR 原资源另存 base64，序列查询保留 ECG、心跳、坐标或数量子样本。SQLite 不解析或执行 Apple 二进制对象。HealthKit 的公开可读对象不等同于 Apple 内部数据库全部内容。

每个已接收有效修订的完整 JSON 同时写入 `raw/apple_health/<user>/<revision>.json`，health_connect 写入 `raw/google_health/`。单条 payload 32 MiB、批次 40 MiB/500 条；超过上限明确失败并保留重试状态，不能截断后推进锚点。类型范围、快照和设备验证缺口见 [支持矩阵](validation/support-matrix.md)。

照片原字节放 `raw/photos/`；HEIC 的处理 JPEG 放 derived，不替代原件。PDF 原字节放 raw/documents。手工录入、OCR 回复及审核历史完整保存 SQLite；导出 v2 将这些表和全部有效原件一起归档。

同步连接标识与来源记录标识分离：两个手机读取同一 Apple Health 数据时，应在来源身份足够可靠时归并同一记录，否则保留候选关系。Android 补入后沿用相同原则。

覆盖状态按用户、连接、数据类型保存：最近查询状态、首次/最近成功同步；可观察时间范围按当前平台/类型查询。失败保留 error 状态而不上传平台错误中的私人内容；客户端列出失败类型。无可读样本、权限未知、未实现、查询失败不能混为“零数据”。

## 去重与派生计算

先按稳定来源身份消除重复传输，再对跨来源事件产生候选，最后计算用户视图。不能仅凭接近的时间或相同值删原记录。报告候选需用户确认；平台规则高置信时自动选择，但保留规则依据及原记录。

每种数据类型定义算法：步数不能把多来源总和相加；睡眠要处理重叠区间；心率均值要说明是样本均值还是按时长加权。尚未定义规则的类型可以归档，但不提供误导的汇总。

聚合返回时间范围、时区、单位、算法版本、来源选择、样本数及数据完整性说明。空集合返回缺失，不返回 0。读取已确认且有效的记录；分析使用同一计算模块，不能让模型自行计算另一套日均值。

首版按需查询有索引的结构化记录。可增加可失效缓存，但缓存键必须包含数据修订水位、时间范围、时区、去重与算法版本；缓存不是原始档案。

## 修改、删除与重新同步

报告删除移除文件、提取、观测及含有其内容的衍生材料；依赖分析立即从有效结果中撤出，再清理含被删数据的快照和正文，只可保留不含健康内容的失效状态。

平台明确删除事件产生最小 tombstone，数据从当前视图和分析移除，相关有效载荷清理；断开授权或查询结果为空不推断全量删除。保留必要来源删除标记防止旧批次复活。用户主动从服务器移除平台记录时亦设抑制标记，重新导入需明确操作。

账户删除撤销会话、取消任务、清理数据库记录与文件及缓存；迟到的模型回复不得重新创建数据。普通记录删除是逻辑/文件清理，不承诺对底层磁盘、SQLite 空闲页或用户离线备份进行取证级抹除。
