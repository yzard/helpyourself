## 载荷结果

同时提交两个健康同步请求，大小分别为 33,554,754 和 41,943,040 字节。单条原始载荷上限 32 MiB、批次正文上限 40 MiB 均被正确接受，超过上限的请求被原子拒绝。原件下载与失去回复后的重试保持一致。

此次服务状态查询采样 9 次，p95 和最大延迟均为 2.95 ms。同步前 RSS 为 58.09 MiB，同步采样峰值为 279.22 MiB。这是单次合成测量，不代表三年历史每日接口的性能验收。ZIP v4 包含相同合成原件，经过重启与副本恢复测试。

组合测试先发现旧断言只允许三份原件。网页流程本身新增其他来源，因此改为记录原有 ID 集合，再核对三份新增原件及全部原件不变。没有放宽载荷大小、重试或内容校验。

## 复现命令

从仓库根目录运行：

```bash
./build_docker.sh
node --test tests/frontend/*.mjs
python3 -m unittest discover -s tests/archive
./build_ios.sh --core-only
python3 tests/docker/deployment.py --load --webgui /absolute/path/to/playwright/index.mjs
```

Rust 命令必须在后端目录运行，以应用该目录的 Cargo 输出配置：

```bash
cd src/backend_api
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test --test backend_api
```

浏览器截图位于 `build/webgui/screenshots/`，载荷摘要位于 `build/deployment-check/load-result.json`。构建产物和合成临时数据不进入源码目录。

## 本轮代码与后台验收

本轮按用户最新要求实现后台和 iOS 代码，不运行 iOS 编译、核心测试、模拟器、真机或 UI 验收。前文 Swift 与浏览器部署结果属于先前阶段，不能证明本轮新增 iOS 页面已通过验证。

新增可执行流程包括五分钟 NN/lnRMSSD、训练协议记录、动作与模板、训练计划、食品与食谱、营养目标、HEI-2020、膳食计划和购物清单、餐食血糖对照、年度报告、提醒、来源引用问答与可删除记忆。FIT 保留完整原字节及解码消息。ECG/FHIR/成对血压和训练圈段提供来源详情。Open Food Facts 查询返回待确认草稿，保存时保留原响应和明确的每 100 克口径。

日结果进入 `daily_views`，源修订清除旧结果并重新排队。测试覆盖同时领取、过期租约、三次失败上限和恢复后的重算。schema 与 ZIP 仍为第一版，现在包含 18 张表。所有新增手动领域继续使用原始载荷、修订和删除契约。

最近全量后台结果为 123 项通过，三年性能测试默认单独运行。随后新增跨七日边界睡眠和来源周期预测两项回归并通过，当前普通测试共 125 项。最终 Clippy 无警告。导出/恢复 9 项通过，网页单元 12 项通过，网页语法与差异空白检查通过。没有重复运行本轮 Docker、真实 OCR、线上模型或 Open Food Facts 在线服务验收。

三年基准包含 1,576,800 条分钟级合成心率记录。首次每日查询为 613.43 毫秒，20 次缓存查询 p95 为 0.89 毫秒，最大 0.92 毫秒。结果达到 500 毫秒缓存预算。[机器信息和完整结果](three-year-query-2026-10-06.json)保留参数。该基准直接生成 SQLite 查询夹具，不验证设备同步或原件吞吐。

汇总现按七个日历日分批，每批最多 50,000 行，最终最多 10,000 个来源日。分批前后核对账户修订。新增结束时间索引，加速近期区间读取。跨批次的睡眠区间仍按当地日期截断，不重复累计。原始档案没有改写。一个七日块仍超限时返回明确错误，不静默丢样本。

研究门禁继续有效：行为关联当前未通过误报率校准，不生成显著发现。PhenoAge 与设备声明的 NN 质量没有真实临床验证。方法实现和单元测试不替代这些证据。

当前不能把整个计划标记完成。仍有食品照片/菜单识别、更多公开健康连接器、Android 客户端及可选小组件/Watch 扩展等代码缺口。真实模型评估、临床资料、完整设备授权历史和真实档案恢复也缺少验收证据。iOS 验证按用户要求暂缓。
