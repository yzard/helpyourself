# 产品范围

## 用户与目标

先供创始人自己使用，美国首发；未来面向规律运动、佩戴健康设备、关注长期健康且可能订阅 Function Health 的用户。首发 iPhone，用户已有 Apple Watch、Apple Health 历史、Function Health PDF 和其他拍照报告。Android 是后续客户端，服务器档案不绑定手机平台。

首个结果是报告准确转换为可核对、可追溯、可比较的数据。主动提出潜在疾病假设是长期核心价值，不以普通 OCR 工具作为最终产品定位。

## 已批准的边界

| 主题 | 决定 |
| --- | --- |
| 数据中心 | 自托管服务器为主档案，手机缓存离线查看，离线可暂存待上传材料 |
| 主权 AI | 核心流程无须经过产品方服务器，包括 OCR；用户自行选择服务 |
| 服务 | Rust 后端协调数据与任务；文档识别、健康分析分别接自建或云端服务 |
| 接口与配置 | OpenAI 兼容模型接口；服务器级 TOML 配置，用户不能单独覆盖 |
| 用户 | 第一版即多用户，独立 users 表及 user_id 归属；管理员建号，无公众注册 |
| 存储 | SQLite 与原件在 API 的统一 data 目录；原件按 apple_health/photos/google_health/documents 分目录；当前直接重构 schema，无 migration |
| 网络 | 后端 HTTP，Caddy 终止对外 TLS，Docker Compose 部署 |
| 平台 | 第一版 iPhone；归档 Apple Health 原始数据，已确认血糖可显式写回；未来接 Health Connect |
| 数据粒度 | 尽可能保存允许读取且用户授权的原始明细；汇总由服务器算法计算 |
| 数据解释 | 原始来源、去重结果、展示汇总分层；不把未读到的数据视为不存在 |
| 同步 | 打开 App 自动同步，支持手动同步；后台尽力执行，显示数据截止时间 |
| 删除 | 平台删除不再用于分析；报告删除清理其数据并使依赖分析失效；账户删除清理其服务器档案 |

## 阶段 A：可信数据闭环

必须交付：

- PDF 和照片上传、持久化后台处理、任务查看和重试。
- 识别、提取、审核、修改、部分确认入档；未确认内容不进入趋势或分析。
- 保留所有发现的项目，包括文字、阴阳性、带比较符号的结果；无法识别的区域可人工补项，不能静默丢失。
- 保留原值、单位、参考区间、采样日期精度、页码与原文定位。可靠换算另存，不能覆盖原值。
- 疑似重复、报告修订、人工修订历史与出处。
- 单项及多项历年趋势，点击检测点回到原报告；不同比例尺清晰分开。
- 可选检查背景：空腹、近期运动、生病、药物或补充剂及备注；未知保持未知。
- Apple Health 分类型读取与服务端明细归档；覆盖进度明确，绝不宣称已支持所有类型。
- 数据导出及删除。导出用于用户迁移，不等于自动备份；首版导入其他实例的工具可后续实施。

## 阶段 B：个人风险分析试用

入口是手动分析及新确认血检数据触发；首个场景为历次血脂相关指标变化与值得向医生讨论的问题。运动、睡眠作为背景，不预设因果关系。

输出必须关联具体数据与日期、核验过的医学来源、其他解释、缺少信息及就医问题。允许提及待验证的疾病假设，但不输出未经验证的患病概率，不把无异常等同于排除疾病。同一问题更新已有记录，结果先放 App 内，不做持续推送。

保留分析时的数据版本、模型与提示版本、算法版本及后续反馈。个人反馈未验证的标为未验证；不能用个人体验取代临床评审。

## 后续阶段

- Android 与 Health Connect：实现第二来源接入及跨平台重复处理。
- 运动恢复、持续分析与通知：独立定义验证目标后建设。
- 公众发布：经临床评审的案例集、适用法规与平台政策评估，以及运营能力准备后决策。

## 暂缓

Excel 导入、WHOOP/Function Health 账户直连、血糖以外的 Apple Health 写回映射、网页客户端、官方多人云托管、开放注册、自动备份和端侧独立运行均不在当前实现。WHOOP 与 Function Health 是用户背景，不等于已承诺直接连接它们的 API。

2026-10-01 用户补充：所有 HealthKit 可读原始数据、照片、OCR 输出及人工添加内容都以本地 API 档案为中心；不能因 Apple Health 无对应类型而丢字段。当前可读类型目录与专门查询已扩大，但完整设备验收仍未完成，见 [支持矩阵](validation/support-matrix.md)。

## 阶段 A 的成功定义

用户从 iPhone 导入真实 Function Health PDF 或照片，校正与确认后能查看可信趋势及原报告；同步中断可恢复、不重复记账、不同用户不可互访；可查看健康明细覆盖范围，并能完整导出自己的原档案与结构化记录。具体证据见 [验证计划](validation.md)。

2026-10-01 服务边界补充：用户明确指定独立 backend_ocr，采用 Qwen3.8 + NInfer；backend_api 接收并归档手机原件，调用 OCR 获取结构化结果。配置及当前验收见 [OCR 运维](runbooks/ocr.md)。
